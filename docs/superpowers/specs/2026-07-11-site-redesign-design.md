# Site Redesign: Jekyll → Astro + Tailwind

**Date:** 2026-07-11
**Goal:** Make the portfolio more digestible for recruiters — a single scrollable homepage in the style of johncarroll.dev — while preserving the deep project write-ups. Replace the Jekyll toolchain with Astro + Tailwind CSS.

## Decisions already made (with Harrison)

- **Structure:** single scrollable homepage; project write-ups stay as separate detail pages.
- **Stack:** Astro + Tailwind CSS. React is available as islands if ever needed, but nothing needs one at launch.
- **Homepage sections:** hero, about (headshot + blurb), featured project spotlight, project grid, skills, footer. No experience/education timeline.
- Harrison approved the section-1 structure and delegated the remaining design decisions.

## Architecture

- **Astro 5** static site, **Tailwind CSS 4** for styling. No client framework; the only client-side JS is the `<model-viewer>` web component (kept for the three projects that have GLTF models) and a few lines for smooth-scroll/nav behavior if needed.
- **Content collection** `projects` replaces the Jekyll `_projects` collection. Schema (zod) mirrors the existing frontmatter so the six markdown files migrate with minimal edits:
  - `title`, `description`, `date`, `categories: string[]`
  - optional: `featured_image`, `github_url`, `thingiverse_url`, `demo_url`
  - optional: `gallery: { file, section?, description }[]`
  - optional: `models: { file, description }[]`, `schematics: { file, description }[]`, `components: { name, quantity?, description?, link? }[]`
  - Jekyll-only keys (`layout`, `interactive_plot`) are dropped from the frontmatter during migration.
- **Markdown bodies migrate verbatim.** Site copy is already in Harrison's voice per `VOICE.md`; the redesign must not rewrite project prose.
- **Assets** stay where they are (`assets/images`, `assets/videos`, `assets/models`, `assets/schematics`, `assets/resume`), moved into Astro's `public/assets/...` (a real move, not a symlink) so all existing `/assets/...` paths in frontmatter and markdown keep working unchanged.

## Pages & URLs

- `/` — the new single-page homepage.
- `/projects/<slug>/` — one page per project, **same slugs/URLs as today** so existing links don't break.
- `/about/` and `/projects/` (the old index) — static redirect pages to `/#about` and `/#projects` via Astro's `redirects` config.
- Dropped: `3d-model-test.html`, the Jekyll RSS feed (portfolio, not a blog). `sitemap.xml` is regenerated by `@astrojs/sitemap`; `robots.txt` kept.

## Homepage sections (top to bottom)

1. **Sticky nav** — name on the left; anchor links About / Projects / Skills; Resume button. Smooth scroll.
2. **Hero** — "Harrison Saperstein", one-line subtitle (keep "Projects and Problems" unless Harrison supplies a new one), buttons: Resume (PDF download), GitHub, LinkedIn.
3. **About** (`#about`) — `assets/images/personal/headshot.jpeg` + a 3–4 sentence first-person blurb condensed from `docs/about.md`, reusing Harrison's own sentences where possible (personal register per VOICE.md).
4. **Featured spotlight** — AR4 Pick-and-Place RL: large card with a looping muted autoplay video (an eval-episode clip from `assets/videos/projects/ar4-pickplace-rl/`), category tags, description from frontmatter, link to the write-up.
5. **Project grid** (`#projects`) — the other five projects as uniform cards: `featured_image` (or a neutral placeholder for projects without one, e.g. Agentic AI Experiments), title, up to two category tags, one-line description. Sorted by date, newest first.
6. **Skills** (`#skills`) — the five existing categories and tags from the current homepage (Robotics, AI/ML, Programming, CAD/Design, Electronics), restyled as a compact grid. Data lives in a small TS/JSON file, not hardcoded in markup.
7. **Footer** — email, GitHub, LinkedIn, Thingiverse, resume link.

## Project detail page

- Header: title, date, category tags, description, external links (GitHub/Thingiverse/demo).
- Body: rendered markdown write-up.
- **Gallery:** frontmatter `gallery` entries render grouped by `section`, images via `<img>`, `.mp4` files via `<video controls>` — matching how the current Jekyll layout presents them (the AR4 and dice pages depend on this).
- **Models/schematics/components:** render when present (`<model-viewer>` for GLTF, image grid for schematics, simple table/list for components).
- Prev/next or "back to all projects" link at the bottom (back-link only; keep it simple).

## Visual design

- Minimal, restrained: generous whitespace, max-width ~72ch for prose, system font stack, one accent color (a desaturated orange — robotics-lab, not startup-blue; final value picked during implementation).
- **Light and dark themes via `prefers-color-scheme`**, no toggle. Tailwind CSS variables for the palette.
- Cards: subtle border + hover lift, no heavy shadows. No emoji, no Font Awesome dependency — inline SVG icons only where genuinely needed (GitHub/LinkedIn marks).
- Motion kept to: smooth scroll, card hover, the featured-project looping video. Respect `prefers-reduced-motion`.
